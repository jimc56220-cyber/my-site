##### 2 浏览器发起 DNS 缓存 

一   浏览器先去查DNS缓存     如果没有

二   浏览器调用操作系统  洋名叫做  Windows DNS cache 

​       再说明白一点就是浏览器也有DNS缓存 他再去看看看  要是实在没办法了

三   浏览器向DNS服务器发请求，然后服务器再向浏览器返回IP，过程结束



##### 3   浏览器建立连接准备

当浏览器 知道 IP和端口 后 开始准备发送 HTTP请求  但是HTTP请求要建立在TCP上  

​	开始TCP三次握手

​		第一次 浏览器 发送 SYN 意思是 “我要建立连接”

​			source port: 52341（随机）（大概意思就是分配 浏览器请求

​			dest port: 8088

​		第二次 服务器收到SYN后 服务器返回SYN和ACK

​			意思是“俺同意”

​		第三次 浏览器再发送ACK 就是说 确认连接 

​	然后建立成功



其实我没太去了解SYN和ACK，大概意思是   SYN / ACK 是 TCP 报文 中 header 里的 flags



我也很好奇第三次连接是在干嘛  查了一下意思就是 客户端能就收到服务器的请求 

我也好奇 TCP连接是解决 连接问题 还是 安全问题 ？ 查了一下 

​	一    确认可以连接

​	二   TCP会给包编号 如果没收到 如果哪个包没收到，那就重新传一次 大名叫——重传机制

​	三   保证网络顺序 因为TCP每个数据包都有序列号 如果网络乱序 TCP会重新排序

​	四   流量控制 如果 客户端接受不过来了  TCP会让传输速度慢一点

9 DispatcherServlet 接管

Dispatcher是   调度   的意思 

DispatcherServlet 就像  总调度中心 调度请求去找对于的Controller

它主要是做四件事



​	一   找Controller

​		比如  请求 GET  /showIndex/services/1

​		它会去找哪个 Controller 可以处理 ？ 然后通过HandlerMapping找到@GetMapping("  /showIndex/services/{id}") 



（我了解到，spring启动的时候会把URL 和 方法 映射在一个 HashMap 数据类型的表上 为什么是 HashMap 我刚开始以为会是数组 因为 修改少   感觉用数组会快一点 然后查了一下说不是的 大概意思是 hashmap 时间复杂度 是 O（1），或者在我的理解中 ，就是从概率学角度，每个数据的查询时间类似，会更稳定，这里面还有一个 很有意思的概率学议题 比如一个问题  要你测一个玻璃从几楼扔下会摔碎 给你两块 在0到100层测试 这里不展开 但是真的很有趣）







​	二   找到后调用方法

​	三   处理参数 比如如果是路径传参 它会找到{id}，如果你的形参是int类型，它还会帮你转换数据类型

​	四   返回处理值  把 Java 返回的 对象  用 SpringMVC（SpringMVC中的 Jackson 库）转成 json 数据 再返回给浏览器（后续去了解的）



还有一个额外的小整理

| 技术       | 作用                  | 转换方向                      |
| ---------- | --------------------- | ----------------------------- |
| MyBatis    | 数据库记录 ↔ Java对象 | SQL结果 → Java对象            |
| Jackson    | Java对象 ↔ JSON       | Java对象 → JSON               |
| Spring MVC | 负责调用 Jackson      | Controller返回对象 → HTTP响应 |
